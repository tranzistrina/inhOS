# INHFS/1 — протокол inhOS USB-UART

Версия прошивки: 0.3.0-alpha (база 0.2.1-alpha). Физический транспорт — CP2102 UART0, **115200 8N1**, без RTS/CTS/XON/XOFF. Native USB CDC выключен. Все целые числа little-endian. Протокол не предоставляет адресного доступа к Flash, NVS, разделам или системным файлам. Это локальный файловый протокол, не механизм аутентификации/шифрования.

## Режим устройства

«Настройки → USB-файлы»: остановить VM, Wi-Fi/web/DNS, индексацию, закрыть файловые дескрипторы, освободить список приложений. Deep-sleep заблокирован до выхода. Разворот экрана и батарейный индикатор сохраняются. Экран показывает ожидание/установленное соединение. 3 клика или удержание отменяют передачу и возвращают главное меню. BYE делает то же программно, после отправки ACK.

Признак usbMode сохраняется в Preferences при входе и очищается при выходе. Поэтому сброс CP2102 при открытии порта возвращает USB-режим. После сброса новый идентификатор сеанса; продолжение частичного файла не допускается. Если соединение оборвалось, текущая передача отменяется после 15 с без корректного запроса. После 60 с без корректных запросов установленный сеанс закрывается, устройство возвращается в обычный режим и восстанавливает штатный таймер сна; GUI отправляет PING каждые 8 с вне передачи. После возвращения из USB обычный таймер сна запускается заново.

Serial-логи и вывод пакетов защищены общим mutex. Во время USB-режима прикладные debug-сообщения подавляются. Ранние ROM/boot-сообщения клиент отбрасывает через фреймер. Любой вывод стороннего кода вне этого mutex в будущем запрещён.

## Кадр

SLIP: начало/конец `C0`, байт `C0` внутри заменяется `DB DC`, `DB` → `DB DD`. Некорректное экранирование, кадр длиннее 536 байт или неполный заголовок отбрасываются до следующего `C0`. Максимум 1074 байта на проводе. Разделитель перед каждым пакетом позволяет восстановиться после boot-текста и обрыва кадра.

| Смещение | Длина | Поле |
|---|---:|---|
| 0 | 2 | ASCII `IF` |
| 2 | 1 | версия 1 |
| 3 | 1 | операция; в ответе установлен бит `0x80` |
| 4 | 4 | seq запроса |
| 8 | 4 | block: смещение байтов для DATA, номер записи для LIST; иначе 0 |
| 12 | 4 | session; 0 только для HELLO |
| 16 | 2 | длина payload 0..512 |
| 18 | 2 | status: в запросе 0, в ответе 0=ACK, остальные NACK |
| 20 | 0..512 | payload |
| 20+N | 4 | CRC32 заголовка и payload |

CRC32 — IEEE, reflected polynomial `0xEDB88320`, initial/final XOR `0xFFFFFFFF`, результат совместим с `zlib.crc32`. CRC включается в SLIP-экранирование. CRC32 каждого пакета дополняется CRC32 всего передаваемого файла.

## Сеанс и повторы

Один запрос одновременно. HELLO содержит ровно ASCII `INHFS/1`, session=0. Ответ содержит ту же строку, ненулевой случайный session (esp_random при входе, новый при каждом новом HELLO). Последующие seq строго возрастают по модулю 2^32, начиная с HELLO.seq+1. Ответ повторяет op, seq, block и session; HELLO возвращает новый session.

Сервер хранит только последний ответ и CRC последнего запроса. Повтор **того же** запроса получает тот же ответ без повторной записи/удаления/сдвига скачивания. Повтор с другим содержимым/старым seq отклоняется. Последний BYE также можно повторить до выхода из режима. Новый HELLO отменяет прежнюю передачу. Клиент не возобновляет передачу после сброса, неизвестного session или исчерпания повторов.

Неправильный CRC кадра при корректном по длине заголовке возвращает NACK 2 без продвижения seq. Нечитаемый заголовок/длина молча отбрасываются. Клиент повторяет запрос при NACK 2/тайм-ауте/повреждённом ответе, до пяти попыток, обычный тайм-аут 2 с. HELLO: до 12 попыток по 2 с (загрузка после сброса). GET_BEGIN/PUT_END/WIPE: до 60 с на попытку. Ответ с допустимым CRC и прочим NACK потребляет seq; BadSession/BadSequence завершают клиентский сеанс. Ошибка CRC **целого файла** — статус 11; старый файл остаётся целым.

## Операции

| Код | Имя | Payload запроса | Payload ACK |
|---:|---|---|---|
| 1 | HELLO | `INHFS/1` | `INHFS/1` |
| 2 | INFO | пусто | JSON: version, protocol, total/free (байты), block_size, max_app, max_book, image_bytes, apps |
| 3 | LIST | пусто; block=индекс записи с нуля | один JSON `{name,size,type}`; пусто = конец |
| 4 | PUT_BEGIN | u32 размер + u32 CRC32 файла + ASCII путь | пусто |
| 5 | PUT_DATA | 1..512 байт; block=смещение | пусто |
| 6 | PUT_END | пусто | пусто после проверки/атомарной замены |
| 7 | GET_BEGIN | ASCII путь | u32 размер + u32 CRC32 файла |
| 8 | GET_DATA | пусто; block=следующее смещение | до 512 байт; после достижения размера клиент отправляет CANCEL |
| 9 | DELETE | ASCII путь | пусто |
| 10 | WIPE | ровно `DELETE USER FILES` (17 байт) | пусто |
| 11 | SLEEP_GET | пусто | ASCII путь выбранной GINH; пусто=встроенная |
| 12 | SLEEP_SET | ASCII путь GINH; пусто=встроенная | сохранённый путь или пусто |
| 13 | CANCEL | пусто | пусто; закрывает файл, удаляет временную копию |
| 14 | BYE | пусто | пусто; CANCEL + выход из USB |
| 15 | PING | пусто | пусто |

Список не обрезается меню на 64 пункта: клиент запрашивает записи по одной до EOF. Типы: app, photo, book. Список содержит только разрешённые пользовательские файлы. Пути начинаются `/`, до 37 ASCII-байт, символы `[A-Za-z0-9_.-]`, без `..`, вложенных каталогов, NUL, слешей после первого. Разрешены только `.inh`, `.ginh`, `/book.txt`; `/book.idx`, NVS и любые бинарные образы недоступны. В процессе загрузки/скачивания изменения файлов и заставки отвергаются как Busy; INFO/LIST/SLEEP_GET/PING/CANCEL/BYE остаются доступны.

NACK: 1 BadPacket, 2 BadCRC, 3 BadSession, 4 BadSequence, 5 BadPath, 6 Busy, 7 IO, 8 Invalid, 9 NoSpace, 10 Confirmation, 11 FileCRC.

## Транзакция записи

1. Проверить путь, размер, наличие свободного места **для новой копии целиком + 8192 байт**. Старый файл не освобождает место, пока не завершена замена. При недостатке места — NoSpace, старый файл цел.
2. Создать `/usb-upload.tmp`, писать строго последовательные блоки, считать полный CRC потоково. Дубликаты обслуживает кеш ответа. Никаких полных книг/приложений в RAM.
3. PUT_END проверяет размер/CRC, flush/close. Повторное чтение с Flash по 512 байт проверяет CRC и UTF-8 без NUL для INH/TXT; для GINH — официальный декодер (3833 байта, заголовок, padding, CRC32 пикселей). INH не компилируется при загрузке.
4. Для книги закрыть дескрипторы и удалить старые индексы **до** замены. Тогда даже при сбое между операциями не останется индекс старой книги того же размера. При следующем открытии книга индексируется штатным ридером.
5. LittleFS VFS `rename(temp,destination)` атомарно заменяет файл; старый destination заранее не удаляется. Ошибка rename оставляет старый файл. После успеха сбросить позицию книги. CANCEL/timeout/выход/загрузка после reset удаляют временный файл.

LittleFS обеспечивает атомарность метаданных rename; электрические power-cut испытания конкретной платы/Flash не проводились. Клиент при скачивании также пишет отдельный локальный `.part`, проверяет полный CRC, fsync и выполняет os.replace. Существующий локальный файл сохраняется при отмене или ошибке.

Удаление книги включает её индексы; WIPE удаляет только пользовательские файлы, индексы и временные загрузки, сбрасывает выбор удалённой заставки/позицию книги. Разворот и прочие настройки NVS, сама NVS, прошивка и разделы не стираются. Для SLEEP_SET изменяется только предназначенный для этого ключ sleepPhoto.
